# Slide 한국어 화면 설계

Slide(`JeongEEE/deckcraft` `my-custom`)의 화면을 한국어로 보여 준다. 원본 DeckCraft는 영어 전용이다.
문구가 코드에 영어로 직접 들어 있고, 번역 목록을 읽는 장치도 언어 설정도 없다
(`docs/localization-parity.md`). 앞 설계(`2026-11-19-slide-fork-design.md`)에서 "나중에 별도 작업"으로
미뤘던 항목이다.

## 왜

소유자가 한국어 macOS·Windows에서 매일 쓸 앱이다. Grid·Word 포크는 한국어 화면이 있는데 Slide만
영어라서, 메뉴와 대화상자를 읽는 데 드는 부담을 없애려고 한다. 요청 원문: "누락없이 한국어로 잘
표시되도록". 성공 기준은 **한국어 환경에서 앱을 열어 평소 쓰는 화면을 다 돌아봐도 영어 문구가
보이지 않는 것**이다. 아래 "영어로 두는 것"은 예외다.

## 목표

1. 리본(탭·그룹·버튼·드롭다운·갤러리 제목·툴팁·키팁 설명), 백스테이지(파일 탭), 메뉴·우클릭 메뉴,
   명령 팔레트·검색, 모든 대화상자, 작업창(서식·애니메이션·선택 창 등), 상태 표시줄, 토스트·오류
   메시지, 슬라이드 쇼·발표자 보기, 포크가 만든 업데이트 카드·모달·About을 한국어로 보여 준다.
2. 엔진이 주는 문구 중 화면에 나오는 것도 한국어로 보여 준다. 명령 이름(`CommandSpec.label`)·메뉴 경로
   (`menu`)·비활성 사유(`disabled_reason`)·사용자에게 보이는 오류 문장이 여기에 든다. 엔진 코드는
   고치지 않고 UI가 그릴 때 번역한다. 값이 끼워 넣어진 엔진 문장은 `{name}` 자리표시자를 둔 영어 틀과
   맞춰 번역한다.
3. 빈 개체 틀의 안내 문구("Click to add title" 등)처럼 캔버스에 보이지만 파일에 저장되지 않는 문구도
   한국어로 보여 준다.
4. 언어 설정은 `auto`(기본, 시스템 언어를 따름) / 한국어 / English 세 가지다. 파일 › 옵션(Preferences)에서
   바꾸고 `prefs.json` 또는 `ui.json`에 저장한다. 다시 시작하지 않아도 바로 바뀐다.
5. **누락 검사가 테스트로 남는다.** 소스의 화면 문구 중 한국어 번역도 "영어로 두는 목록" 항목도 아닌
   것이 있으면 실패한다. 업스트림을 병합해 새 문구가 들어오면 이 테스트가 바로 알려 준다.
6. Windows 설치 마법사와 Mac DMG 안내는 앞 작업에서 이미 한국어다. 이번 작업에서는 실제 산출물로 다시
   확인한다. DMG는 Mac에서 열어 보고, MSI 화면은 소유자 Windows PC에서 빌드한 뒤 확인한다.
7. 한국어 화면을 0.19.1에 넣는다. 0.19.1은 Mac 초안만 올라가 있고 태그는 원격에 없다. 다시 빌드해
   초안 자산을 바꾼 뒤 Windows 빌드를 올리고 finalize로 공개한다.

## 비목표

- 한국어 외 언어. 장치는 언어를 더할 수 있게 두되 목록에는 한국어만 넣는다.
- CLI(`deckcraft-cli`/`slide-cli`)·MCP·제어 채널·로그 메시지. 스크립트와 에이전트가 영어 문구에
  기대므로 번역하지 않는다.
- 엔진 crate 수정. 병합 충돌을 줄이려고 엔진·모델은 건드리지 않는다. 화면 표시 쪽에서 해결한다.
- craft-i18n 저장소에 한국어 `deckcraft.tsv`를 올리는 일(업스트림 기여).

## 안티 목표: 동작은 하지만 실패인 경우

- **문서 내용이 번역된다.** 슬라이드 텍스트, 레이아웃·마스터·테마 이름, 개체 이름처럼 파일에
  저장되는 값이 한국어로 바뀌어 저장되면 실패다. 파일을 PowerPoint에서 열었을 때 원본과 달라진다.
  레이아웃 이름 등은 **화면 목록에 표시할 때만** 번역하고 저장 값은 영어 그대로 둔다.
- **명령 ID·저장 상태가 언어에 따라 바뀐다.** 명령 ID, 저장된 탭·창 상태, 접히는 영역의 egui ID가
  표시 문구에서 만들어지면, 언어를 바꿀 때 열림 상태가 풀리거나 저장된 배치가 깨진다. ID는 영어
  원문으로 고정한다.
- **기존 테스트가 한국어 Mac에서만 깨진다.** UI 테스트 61개 파일이 영어 라벨로 버튼을 찾는다.
  테스트는 언어 설정과 무관하게 영어로 돌아야 한다. 현재 언어는 스레드별 값이고 기본은 English이며,
  앱이 설정에서 읽어 매 프레임 지정한다(Word와 같다).
- **번역 문구가 칸을 넘친다.** 리본 버튼·작은 버튼·상태 표시줄·대화상자 라벨 열에서 한국어가 잘리거나
  겹치면 실패다. 좁은 곳은 짧은 번역을 쓴다(`@context` 행 또는 짧은 문구 선택).
- **자리표시자가 깨진다.** `{n}`·`{name}`·말줄임표 `…`·줄바꿈이 원문과 번역에서 다르면 화면에 `{n}`이
  그대로 나오거나 값이 빠진다. 테스트로 막는다.
- **번역 품질이 기계 번역 같다.** PowerPoint 한국어판에서 익숙한 용어 체계(슬라이드 쇼, 개체 틀, 전환,
  애니메이션 창, 서식, 맞춤 등)를 기준으로 하되, 다른 제품의 번역 표를 베끼지 않는다. craft-i18n의
  clean room 원칙("일반 컴퓨팅 용어로 영어 뜻을 보고 쓴다")을 따른다. `ko/common.tsv`·Word 포크의 한국어
  용어와 같은 말은 같은 번역을 쓴다.

## 제약

- Rust 워크스페이스 규칙: 레이어 규칙(`cargo xtask layers`). 번역 코드는 L7 `ui-egui` 안에만 둔다.
  never-crash 규칙(unwrap/expect/panic 금지). `cargo xtask ci` 8단계는 `CRAFT_FONTS_DIR`를 넣고
  전부 통과해야 한다.
- **새 외부 의존성 없음.** `craft-i18n` crate(craft-libs rev `63196e66f3033a6623eb629af95a104d26986725`)는
  craft-ui를 통해 이미 `Cargo.lock`에 있다. `ui-egui`의 직접 의존으로 같은 rev를 적는다.
- 번역 목록은 **이 레포 안에** 둔다. Word처럼 빌드할 때 외부 craft-i18n 체크아웃(`CRAFT_I18N_DIR`)을 받게
  하지 않는다. Windows·Mac 배포 스크립트와 빌드 환경을 바꾸지 않기 위해서다.
  - `i18n/ko/common.tsv`: craft-i18n `locales/ko/common.tsv` 사본. 출처 커밋을 파일 머리 주석과
    `ATTRIBUTION.md`에 적는다(Apache-2.0). 갱신은 손으로 복사한다. 출처는 craft-i18n main
    `b5b2805795f3d98b8fef4484db75db0cefbdc630`(2026-11-20)이다. 이 파일을 마지막으로 바꾼 커밋은
    `c5edd3c9`다. 받는 명령은
    `gh api repos/storytold/craft-i18n/contents/locales/ko/common.tsv?ref=<SHA> -H "Accept: application/vnd.github.raw"`이다.
    Word 포크(`e56d2624`)보다 새 커밋이므로 같은 키의 번역이 Word와 다르면 이 사본을 따른다(구현자 판단).
  - `i18n/ko/deckcraft.tsv`: 포크가 쓰는 Slide 한국어 목록. 형식은 craft-i18n TSV와 같고(context, 영어,
    번역), 키는 원본 `locales/de/deckcraft.tsv`처럼 영어 원문 그대로다. 원본이 나중에 목록 읽는 장치를
    들이면 이 파일을 그대로 옮길 수 있다.
  - 두 파일은 `include_str!`로 `craft_i18n::Embedded`에 넣는다. build.rs는 필요 없다.
- 한국어 글꼴: UI 글꼴 대체(`uifonts.rs`/`theme.rs`)에 이미 한글이 있다(macOS Apple SD Gothic Neo,
  Windows Malgun Gothic). 실제 앱 화면에서 네모(tofu)가 나오지 않는지 확인한다.
- 커밋 규칙: 한국어 Conventional Commits, AI 표식 금지, 바꾼 파일만 경로로 add. Task 하나가 리뷰를
  통과할 때마다 커밋·푸시한다.

## 접근 방식

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. craft-i18n + 레포 안 한국어 목록 (선택)** | Word와 같은 번역 함수(`t`/`tc`/`tn`/`fmt`), 원본 craft-i18n과 같은 TSV 형식·키 | 원본의 향후 방향(craft-i18n 목록)과 키가 맞는다. 공통 한국어 1,250줄을 그대로 쓴다. 의존성 추가 없음 | 원본 파일 여러 곳을 고쳐 병합 충돌이 는다 |
| B. Grid식 Rust 표(`ko.rs`) | 영어→한국어 HashMap을 Rust 코드로 둔다 | 단순하다 | 공통 목록을 다시 써야 한다. 원본 형식과 달라 나중에 옮겨야 한다 |
| C. 그리기 단계에서 일괄 치환 | egui 글자 그리기를 가로채 영어 문자열을 바꾼다 | 원본 파일을 거의 안 고친다 | 슬라이드 내용·사용자 입력까지 바뀔 수 있다. 위 안티 목표 1번 위반이라 버린다 |

소유자가 A를 승인했다(2026-11-20).

## 설계

### 번역 모듈 `crates/ui-egui/src/i18n.rs`

Word의 `wordcraft/crates/ui-egui/src/i18n.rs`(포크 `my-custom`)를 참고하되, 필요한 만큼만 옮긴다.

- `static I18N: LazyLock<craft_i18n::I18n>`: `[("ko", common, deckcraft)]`로 만든다.
- 스레드별 `CURRENT` 언어(기본 English). `set_current`, `current`.
- `t(s)`: 현재 언어 번역, 없으면 영어. `tc(context, s)`: 문맥 번역. `tn(n, one, other)`: 개수 문구.
  `fmt(template, args)`: 번역한 틀에 값 채우기(craft-i18n `fmt`).
- `t_dynamic(s)`: 엔진이 값을 끼워 만든 문장을 `{…}` 틀 목록과 맞춰 번역한다. 맞는 틀이 없으면 영어.
- 설정값 `language`: `"auto" | "ko" | "en"`. `auto`는 `I18N.system_lang()`으로 시스템 언어를 따른다.

### 번역을 거치는 지점

1. **공용 위젯 안에서 번역**: `widgets.rs`의 `big_button`·`small_button`·`check_item`·`dropdown`·`section`·
   `spinner`·`icon_toggle`·`color_split`·`gallery`·`drop_button` 등은 라벨·툴팁을 받은 뒤 그리기 직전에
   `t()`를 거친다. 한 번 고치면 호출부 수백 곳이 함께 바뀐다. 라벨로 egui ID를 만드는 곳은 영어 원문을
   ID로 쓴다.
2. **egui 직접 호출**: `ui.label("…")`·`ui.button("…")`·`on_hover_text("…")`·`selectable_label`·`checkbox`·
   `RichText::new("…")`·창 제목 등은 호출부에서 `t("…")`로 감싼다. 대략 600곳이다.
3. **`format!`으로 만든 문장**: 영어 틀을 키로 `fmt(t("Slide {n} of {total}"), …)`처럼 바꾼다. 영어 화면의
   문구는 그대로여야 한다.
4. **엔진 문구**: 명령 팔레트·메뉴·툴팁·토스트·오류 표시 지점에서 `t()`(고정 문구) 또는
   `t_dynamic()`(값이 끼워진 문구)을 거친다.
5. **화면 표시용 문서 이름**: 레이아웃 갤러리·테마 갤러리·빈 개체 틀 안내 문구는 표시할 때만 번역한다.
   저장 값은 바꾸지 않는다.

### 설정 화면

Preferences 대화상자 일반 영역에 "Language / 언어" 드롭다운(자동(시스템) / 한국어 / English)을 둔다.
라벨 자체도 번역된다. 저장 위치는 구현자가 `Prefs`(엔진)와 `UiState`(UI) 중 고른다. 엔진을 고치지
않는다는 제약 때문에 `UiState` 쪽을 우선한다.

### 누락 검사

`crates/ui-egui/src/i18n/tests.rs`에 둔다.

- **소스 검사**: `crates/ui-egui/src`(테스트 파일 제외)와 엔진의 사용자에게 보이는 문구 출처(명령 label·
  menu, disabled reason·오류 문장)에서 화면 문구 후보를 모은다. 각 후보가 ko 번역을 갖거나
  `i18n/keep_english.txt`(영어로 두는 목록, 항목마다 이유)에 있어야 통과한다. 후보를 고르는 규칙(대문자로
  시작하는 문자열 리터럴, 공용 위젯·egui 텍스트 함수 인자 등)과 제외 규칙(ID, 로그, serde 키, 파일 확장자)은
  구현하며 정하고 테스트 문서 주석에 적는다. 계획에는 "규칙 1차안 → 실제 후보 수 측정 → 조정" 단계를
  넣는다. 테스트가 엔진 소스를 **읽기만** 하는 것은 "엔진 수정 금지"에 걸리지 않는다. 앞에서 적은
  "대략 600곳"은 여러 호출 형태를 대충 합친 추정치다. 실제 수는 이 측정으로 정한다.
- **목록 검사**: 모든 번역 행의 자리표시자 집합·말줄임표·줄바꿈 개수가 영어와 같다. `keep_english.txt`의
  항목이 실제 소스에 아직 있다(죽은 항목 금지). 번역 목록에 중복 키가 없다.
- **표시 검사**: 한국어로 지정한 egui 테스트 하네스에서 주요 화면(리본 각 탭, 백스테이지, Preferences,
  주요 대화상자)을 그린 뒤, 그려진 글자에 번역 안 된 영어 라벨이 없는지 본다. 기존 UI 테스트는 영어 그대로
  통과해야 한다.
- 실제 앱 점검: 한국어로 `Slide.app`을 띄워 리본 탭 전부, 백스테이지, 대화상자 열 몇 개, 슬라이드 쇼를
  스크린샷으로 보고 잘림·겹침·네모 글자를 확인한다.

## 영어로 두는 것

- 파일 형식 이름("DeckCraft Presentation"), 테마 이름 "DeckCraft", 글꼴 이름, 단위 기호(pt, cm, px),
  단축키 표기(⌘, Ctrl+…), 색 코드, 파일 확장자.
- 슬라이드에 들어 있는 문서 내용, 저장되는 레이아웃·마스터 이름(표시만 번역).
- About의 원본 저작권·라이선스 원문.
- CLI·MCP·제어 채널·로그.

## 구현자에게 맡기는 것

- 화면 문구 후보를 뽑는 정확한 규칙과 `keep_english.txt`의 형식.
- 번역 문구 자체. 기준은 위 품질 원칙과 기존 용어 일관성이다.
- 좁은 칸에서 짧은 번역을 쓸지, `tc` 문맥 행을 쓸지.
- 언어 설정 저장 위치(`UiState` 우선).
- Task 나누기. 영역별(리본 탭 묶음, 대화상자 묶음, 백스테이지·작업창, 엔진 문구)로 나누고 각 Task가 누락
  검사의 해당 범위를 통과하게 하는 방식을 권장한다.
